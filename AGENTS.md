# Repository instructions

- Please ask me any clarifying questions before proceeding.
- Do not code until I confirm the plan.
- Write a plan to `plan.md` before starting complex tasks.

## Persist learning explanations

- Save substantive explanations from the learning conversation in
  `learning-notes/` during the same task. Include Java concepts, Git workflow,
  and explanations arising from exercise reviews.
- Update the relevant topic note, or add a topic note and link it from
  `learning-notes/README.md`.
- Keep the examples and step-by-step explanations needed for later revision.
  Add short recaps and useful questions; avoid copying the conversation verbatim.
- Link related topics and relevant exercise files. Keep the notes together
  in this folder.
- Follow the structure documented in `learning-notes/README.md`: concept
  chapters go in `explanations/`, exercise-specific feedback in
  `exercise-reviews/`, and compact recall material in `revision/`.
- Keep one chapter per concept and one review file per exercise. Append
  dated review checkpoints and link to the main explanation instead of
  duplicating it inside the review.
- Update `learning-notes/progress.md` after reviews. Distinguish verified
  code behavior from the learner's reported or demonstrated understanding.
- Introduce unfamiliar APIs with purpose, input/result contracts, and an
  example before assigning exercises that require them. Complete example
  programs should include imports and expected output.
